# ORRERY Windows版 0.2.0（実装プレビュー）

[ito-ops/orrery](https://github.com/ito-ops/orrery)のMac専用HUDをWindows向けに再実装しました。元のSwiftコードは残し、Windows版を`windows/`に追加しています。公式Windowsリリースではありません。

## 最初に使う

対象は **Windows 11 / x64** です。

1. `Orrery-Windows-0.2.0-x64.zip` を右クリック→「すべて展開」。
2. 展開フォルダー内の`Orrery.exe`を開きます。exeだけを別の場所へ移動せず、フォルダー全体を保管してください。
3. 時計・PC情報が表示されます。天気・株価にはインターネット接続が必要です。
4. 「再生音 OFF」でPCの音に、「マイク OFF」で自分の声にリングが反応します。もう一度押すと停止します。

この成果物はLinux上でWindows用に組み立てたプレビューで、**Windows実機ではまだ動作確認していません**。署名・自動更新はありません。出所を確認し、組織の実行制限は管理者の方針に従ってください。

実行用ZIPにはElectronと音声取得ヘルパーの.NETランタイムを含みます。使う人がNode.jsや.NETを別途入れる必要はありません。

## 今回追加した機能

| 機能 | 使い方・条件 |
| --- | --- |
| カスタムカラー | 設定→テーマを「カスタム」にして色を選択 |
| パネル個別表示 | 時計・PC情報・Claude使用量・天気・相場・粒子を個別ON/OFF。左右のパネルがすべて非表示なら中央が広がる |
| ウィンドウ位置の復元 | 位置とサイズを保存。モニターが外れた場合は残った画面内に収める |

| 背面表示から戻す | Windows通知領域の水色アイコンをクリック→通常表示。右クリックメニューから設定・最前面・終了も操作可能 |
| 指定アプリだけの音 | 設定→音の取得対象→指定アプリのみ。対象exeを選び、アプリを起動して「指定アプリ OFF」を押す |
| 新規チャットの作成 | 設定→起動時の自動操作→新しいチャットを作成 |
| 新規チャット＋音声開始 | 設定→起動時の自動操作→新しいチャット＋音声開始。対象アプリの対応ボタンが必要 |
| 会話中の音声起動停止 | ORRERYから音声会話を開始する直前に自動で待受を停止。終了操作後に、もともとONだった場合だけ待受を再開 |
| Claude料金概算 | モデル名ごとに自分で単価を登録。入力・出力・キャッシュ読み・キャッシュ書きの4項目。未登録モデルは計算から除外し、件数を表示 |
| 環境変数 | 地点・音源・配色・自動操作などを設定画面より優先して指定可能 |

### 指定アプリだけの音

Windowsのプロセスループバックを利用し、指定したexeのプロセスと子プロセスの再生音を解析します。OSビルド20348以降が必要で、Windows 11を推奨対象としています。

- 対象アプリを起動し、そのexeに一致するウィンドウ付きプロセスが1つある状態にしてください。
- 実際のアプリ本体のexeを選びます。ランチャー・ショートカット・権限で実行パスを取得できないアプリは対象にできないことがあります。
- 取得に失敗してもPC全体の音へ自動で切り替わりません。取得中のアプリが終了すると停止します。
- 音声は補助プロセス内で周波数ごとの強さに変換します。生の音声は画面プロセスへ送らず、保存・ネットワーク送信もしません。
- マイクと同時利用すると、周波数ごとに大きい方を画面に反映します。

「PC全体の再生音」はElectronの画面キャプチャAPIを音声取得に使用します。APIの都合で作成される映像トラックは直ちに停止し、映像・音声を保存しません。

### Codexの自動操作と会話中の待受

起動先は設定から自分で選びます。Windows UI Automationを使い、指定exeのウィンドウ内にある対応ボタンだけを操作します。新規チャットではNew chat / New task / New threadなどのボタン名や既知のID、音声ではStart voice modeなどを確認します。

**Codexのすべてのバージョンで使えると保証するものではありません。** 音声機能がない・アクセシビリティ情報を公開していない・ボタン名が異なる・複数候補がある場合は失敗理由を表示します。推測したグローバルショートカットは送りません。音声開始のボタンが見つからない場合は新規チャットも作成しません。

1. 必要なら「音声起動」をONにします。
2. 「CODEX と話す」または合図で、新しいチャットと音声会話を開始します。
3. 待受表示が「一時停止」になります。会話中の声で再起動しません。
4. 「会話終了」で起動先の音声終了ボタンを操作し、もともとONだった待受を再開します。
5. 終了ボタンを確認できない場合は待受を止めたままにします。**起動先で音声会話を終了してから**「起動先で終了済み・待受を再開」を押してください。

ORRERYを通さず起動先で手動開始した会話や、起動先での手動終了は自動検出しません。手動開始前には待受をOFFにしてください。自動操作の途中で失敗し開始状態が不確かな場合も、確認するまで待受を止めます。

## 音声起動

設定で起動先.exeと合図、認識言語を指定します。合図はカンマ区切りで8件まで（例`オレリー,hey codex`）、言語は既定`ja-JP`。

Windows標準のSystem.Speechによる端末内認識です。対応する音声認識エンジンとマイクの許可が必要です。「設定→時刻と言語」で音声機能を追加し、「プライバシーとセキュリティ→マイク」でデスクトップアプリの利用を許可してください。音声言語が未導入の場合や、PowerShellの実行ポリシーに拒否された場合はエラーを表示します。OSのポリシーを自動変更・回避しません。

音声起動は6秒間の連続起動抑制があります。設定保存・起動先変更・アプリ終了で停止します。アプリ再起動時には自動でマイクを開かず、ボタンでONにします。

## その他の設定

- 天気：地名だけでなく緯度・経度も指定。大阪なら`OSAKA / 34.6937 / 135.5023`。
- 相場：`^N225:日経225,JPY=X:USD/JPY,BTC-USD:BITCOIN`のように10件まで。
- 描画：粒子数・FPS・静止モード。待機中は最大12FPS、最小化中は描画停止。
- 通常・最前面・背面の切替：右上の「表示」または設定、Windows通知領域から操作。
- 会話・アプリ自動操作中は設定と起動先を変更できません。会話終了後に変更してください。

### 料金概算用の単価

設定のJSON欄に、ログ内の正確なモデル名と**100万トークンあたりのUSD単価**を登録します。

```json
[
  {"model":"実際のモデル名","input":0,"output":0,"cacheRead":0,"cacheWrite":0}
]
```

上の0は書式例です。実際に使う料金表の値へ置き換えてください。単価の初期値は空配列`[]`で、根拠のないモデル単価は埋めていません。モデル名は完全一致です。ログの重複を除いて最終トークン数に掛け、概算USDを表示します。サブスクリプション料金・割引・契約価格を表す請求額ではありません。

Claude使用量は`%USERPROFILE%\.claude\projects`のJSONLを全期間集計します。上限2000ファイル・深さ8、制限時は一部集計と表示。入力・出力・キャッシュのメタデータだけを表示し、会話本文は表示・送信・別保存しません。

### 環境変数

優先順は **環境変数 > 設定画面 > 既定値**。

| 変数 | 内容 |
| --- | --- |
| HUD_CITY / HUD_LAT / HUD_LON | 地名・緯度・経度 |
| HUD_TICKERS | 銘柄一覧 |
| HUD_GRAINS / HUD_FPS / HUD_STATIC | 粒子数・FPS・静止（0/1） |
| HUD_THEME / HUD_COLOR | テーマ名（CUSTOMなど）・#RRGGBB |
| HUD_AUDIO_MODE | system または app |
| HUD_WINDOW_MODE | normal / topmost / desktop |
| HUD_AUTOMATION | open / newChat / voice |
| HUD_WAKE_PHRASES / HUD_WAKE_LOCALE | 合図一覧・音声言語 |
| HUD_APP_PATH | 対象exeの絶対パス |
| HUD_PRICES | 単価JSON配列 |

設定は`%APPDATA%\orrery-windows\settings.json`に保存します。実際のフォルダー名は環境により製品名になります。

## ソースから使う

開発する人は **Node.js 24 LTS** と **.NET SDK 10** をインストールしてください。ビルドとは、ソースコードから実行できるプログラムを組み立てることです。

ソースZIPを展開し、PowerShellで`orrery\windows`へ移動して実行します。

```powershell
npm ci
npm test
npm start
```

`npm start`は先にWindows用音声ヘルパーをビルドします。初回は依存パッケージや.NETランタイムをダウンロードするため通信が必要です。

```powershell
npm run dist
```

`dist`にx64のセットアップ.exeとZIPを生成します。GitHub ActionsにもWindows上でPowerShell構文・C#コード・Nodeテスト・画面テスト・Electronテストを実行してからビルドするワークフローを追加しています。この作業ではGitHubへpushもActions実行もしていません。

## 検証と残る条件

Nodeの17テスト、Chromiumの模擬画面操作、Windows用ヘルパーのコンパイル、合成音波・無音でのFFTを検証しました。詳細は`VERIFICATION.md`。

**Windowsの音声デバイス、Explorerへの実際の配置、実際のCodexのUI操作、インストーラーの動作はWindows実機で未検証です。** 実装があることと実機で動作確認できたことを区別しています。Windowsや対象アプリの条件を満たせない機能は、エラー表示して停止します。

天気はOpen-Meteoへ緯度経度、相場はYahoo Financeへ銘柄を送信します。音声・会話ログ・設定ファイルは送信しません。元プロジェクトのMITライセンスと著作権表示を同梱しています。
